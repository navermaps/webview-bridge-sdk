getWebviewContext()

Parses the User-Agent string to determine whether the page is running inside the NAVER Maps app at a supported version, and extracts the app's current UI context (theme and orientation).

This function works in both server and client environments, making it suitable for SSR frameworks that need to detect the app context before the page reaches the browser (e.g. to pick the correct theme on the server side before rendering).

Signature​

function getWebviewContext(params: {
  userAgentHeader: string
  supportedAppVersion?: string
}): GetWebviewContextResult

Parameters​

userAgentHeaderstringRequired
The User-Agent string to parse. On the client, pass window.navigator.userAgent. On the server, pass the User-Agent request header.
supportedAppVersionstringOptional
The minimum app version required for SDK support. Defaults to 6.0.0. Versions below this threshold will result in isSupported: false.
default: 6.0.0

Return Value​

isSupportedbooleanRequired
true if the page is running inside the NAVER Maps app at or above the supported version. false otherwise (e.g. running in a regular browser, or on an older app version).
themestringOptional
The app's current color scheme: light or dark. Present only when isSupported is true.
orientationstringOptional
The device's current orientation: portrait or landscape. Present only when isSupported is true.

User-Agent Format​

When the NAVER Maps app opens a webview, it appends the following token to the User-Agent string:

WebViewSDK(map; {theme}; {orientation})

Examples​

Client-side:

import { getWebviewContext } from '@maps-service/maps-bridge'

const { isSupported, theme, orientation } = getWebviewContext({
  userAgentHeader: window.navigator.userAgent,
})

if (isSupported) {
  console.log(`Theme: ${theme}, Orientation: ${orientation}`)
}

Server-side (Next.js example):

import { getWebviewContext } from '@maps-service/maps-bridge'

export async function getServerSideProps(context) {
  const userAgent = context.req.headers['user-agent'] ?? ''
  const { isSupported, theme } = getWebviewContext({ userAgentHeader: userAgent })

  return {
    props: {
      initialTheme: theme ?? 'light',
      isSupportedApp: isSupported,
    },
  }
}
tip

On the client, prefer CSS media queries for reacting to theme and orientation changes. Use getWebviewContext() only when you need the initial values at SSR time or for server-side logging.
